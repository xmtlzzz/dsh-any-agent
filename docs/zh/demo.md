# ▶️ 5 分钟：派活 → 插话 → 验收

这个页面不是功能列表，是一条**能跑通**的路径。跑完你会看到：一个 agent 在后台把活干完、你中途改过两次需求、最后你自己复核了它交的东西 —— 而不是只看它说"已完成"。

```bash
npm run demo
```

## 它解决的是什么问题

你的编辑器里已经有一个编码 agent，它卡在你的窗口里：你一关编辑器，它就没了；你想改口，只能等它跑完。

`dsh-any-agent` 把 DSH 变成**别的 agent 的后台同事**：你在 Claude Code / Codex / Cursor 里派活，它在后台跑，跑完由哨兵文件通知你。这条 demo 就是那套流程的最小可跑版本。

## 0. 准备

- **Node.js ≥ 22.15**（服务端用 `node:zlib` 的 `zstdDecompressSync` 读会话头，更早的版本没有这个 API）
- **一份能用的 DSH**：`npm i -g @deepseek-ai/dsh`，并且 `~/.dsh` 里有可用的 provider 与凭据（DSH 的 GUI 里能正常聊天就说明配好了）
- 不需要装 Claude Code / Codex —— demo 自己就是一个 MCP 客户端

## 1. 跑

```bash
npm run demo
```

它会在临时目录里建一个空工作区，然后让 DSH 在里面写两个文件（`fib.mjs` 与 `test-fib.mjs`）并跑测试。**中途会插两次话**：

1. 要求 `fib(n)` 对负数抛 `RangeError`，测试里补一条断言；
2. 要求在 `fib.mjs` 顶部加一行复杂度注释。

跑完脚本**自己会复核**：检查两个文件是否真的存在，并亲手跑一遍 `node --test test-fib.mjs`。模型的自我汇报在这里不算数。

实测：本机（Windows / Node 24.21.0 / 默认 profile）一次完整跑完 **57.6 秒**，三个回合、两次插话、4 个测试用例全过。换模型会浮动，但这就是"5 分钟"的来源 —— 留足余量。

## 2. 六步分别做了什么、为什么需要它

| 步骤 | 工具 | 为什么这一步重要 |
|---|---|---|
| 1 | `initialize` / `tools/list` | 只走 4 个标准 MCP 方法；任何支持 MCP over stdio 的客户端都能接 |
| 2 | `dsh_start` | 建一个**长驻**会话。身份是磁盘上的 `sessionId`，进程只是缓存 |
| 3 | `dsh_send(wait=false)` | 派完立刻返回 `run_id` + `sentinel_file`，回合在后台跑 —— 别让客户端自己的超时把你的活掐掉 |
| 4 | `dsh_interject` ×2 | 中途改口。走的是"取消 + 立刻开新回合"，**已经做的工作不丢** |
| 5 | 读哨兵 | **一个回合 = 一个哨兵**：被打断那轮写 `cancelled`，最后一轮写 `done`。文件原子落地，服务中途重启也照样能读 |
| 6 | `dsh_get` + 自己复核 | `run_id` 是验收凭据；但结论要靠磁盘上有什么，不靠模型说了什么 |

## 3. 三个容易被忽略的设计

**为什么第 3 步不等结果？** 因为 MCP 工具调用是阻塞的，而客户端的响应超时通常只有几分钟。`wait=false` 让"派活"这个动作瞬间返回，长任务用**哨兵文件**收尾 —— 这才是"把几小时的活交出去"的前提。

**`dsh_interject` 会一直等到"改口后的那一轮"结束才返回。** 它不是一个"发出去就回"的通知：你看到的第 4 步耗时里包含了一整轮模型工作。这通常是好事（返回即代表改口已经生效），但要给它留够时间 —— 用 `timeout_ms` 设上限，等不到空闲会报错并把你这次插话按 `cancelled` 落地（**不会**留在队列里偷偷执行）。

**插话为什么不毁掉已经做的工作？** ACP 明确拒绝并发 prompt（`a prompt is already in flight`），所以 `dsh_interject` 是"取消当前回合 + 立刻发新回合"，历史完整保留。这是实用等价物，不是真·中途改向 —— 见[已知限制](limits.md)第 2 条。

**为什么 demo 用 `workspace-write` 而不是默认档？** 为了让沙箱真的在起作用：这个任务只该写临时工作区里的两个文件。`read-only` 档连 shell 都起不来，`danger-full-access` 又不适合当默认示范。

## 4. 换一个任务 / 零成本预览

```bash
# 换成你自己的任务（会跳过内置的三个小要求）
npm run demo -- --prompt "把这个目录里的 README 翻译成英文，并检查 Markdown 语法"

# 回放上一次录制：不需要 DSH、不花 token、几秒钟看完
npm run demo -- --replay

# 跑完保留工作区，方便自己翻结果
npm run demo -- --keep
```

想把它录成一份可回放的记录：

```bash
npm run demo -- --save      # 成功后写 demo/transcript.json
```

## 5. 隔离性：它不会动你的日常状态

注册表、哨兵、写锁登记全部指向一个临时目录，脚本结束时删掉。也就是说：**跑 demo 不会污染你在 Claude Code 里真实使用的那套会话列表。**

只有一件东西仍在 `~/.dsh` 里：DSH 自己的会话日志（凭据和 provider 在那儿，没法隔离）。脚本结束时会 `dsh_release(forget=true)` 把这个会话从注册表里移走。

## 6. 它证明了什么、没证明什么

**证明了**：MCP 握手通了、会话建得起来、后台派活收得到哨兵、插话能让任务改向且不崩、产出物落盘且测试真的能跑过。

**没证明**：你的机器上模型一定按预期行事（不同模型差异很大）、长任务在几小时后仍然可用（demo 只跑几分钟）、以及并发多会话时的表现 —— 那些在[测试](tests.md)里另有覆盖。

> 需要说明的是：**demo 会真的调用模型、真的花 token**。想先看流程再决定要不要跑，就先用 `--replay`。
