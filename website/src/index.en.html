GOOD QUESTIONS

What you may want to know first.

Key mechanisms and operational boundaries at a glance. Detailed guides are in the docs.

How is this different from calling the DSH CLI directly?

This project drives long-lived DSH sessions over ACP: resume history, interrupt turns, handle approvals, and dispatch now while collecting later. The client sees sessions and tasks, not a list of shell commands to execute one by one.

What happens if the editor closes or a process crashes?

Persisted sessions can be resumed on the next call. In-flight turns stop when the server or child process exits, and a sentinel may not land. After resuming, check the workspace before dispatching again. Normal turns notify via atomic sentinel files (with ready-made PowerShell wait commands on Windows), avoiding polling. A session that dies before its first successful turn may not have reached disk.

Do I need a specific editor, model, or API provider?

Any client that can launch a stdio MCP server can connect. Model routing reuses your existing DSH configuration; this project bundles no model credentials and resells no model service. Model usage is billed by your provider.

How do I control write access, sandboxing, and approvals?

Choose read-only (enforces auto-deny and fail-closed verification against the actual sandbox), workspace-write (both server & setup default), or danger-full-access (requires DSH_MCP_ALLOW_FULL_ACCESS=1 on both new & resumed sessions). Workspace snapshots disable repository .git/config clean filters/fsmonitor and block cross-drive junctions plus home/disk-root cwds. Out-of-workspace approvals default to auto-allow and are audited in the review ticket; pass on_approval=ask to adjudicate via dsh_inbox / dsh_approval_decide. Side effects of external MCP tools are outside DSH's sandbox; read usage notes and security policy.

Can I operate the same session in the DSH GUI at the same time?

Only one writer per session at a time. While this server holds the lock, opening the session in the GUI is read-only (you can inspect turns and output safely without losing the lock); opening an idle, unlocked session in the GUI permanently acquires a write handle until dsh web is restarted. To watch progress use dsh-any-agent watch / dashboard (they only read event files and never touch the lock), or have the agent use dsh_read; call dsh_release before taking over in the GUI. See the write lock guide.

How do I watch live progress, token spend, and switch languages?

Since 0.6.1, run dsh-any-agent watch in a terminal or dsh-any-agent dashboard for a local read-only web page showing the call chain and live token/cache usage (binds 127.0.0.1 with a one-time token, redacts previews, strips terminal OSC 52 control sequences, and never writes reasoning). Tool titles, descriptions, returned results and review tickets all follow the system language or DSH_MCP_LANG=en|zh, and blocking calls with progressToken push updates every 5 seconds. Details in the usage guide.

What is team mode, and how do I enable it?

Off by default since 0.5.0; opt in as needed: run dsh-any-agent team on and reconnect. DSH can then form named teams when a task needs parallel or multi-role work, while simple tasks stay single-agent. Turn it off globally with dsh-any-agent team off, or for a single turn with dsh_send(team=false). Full steps are in the team mode guide.

Which DSH versions are supported, and does it detect the desktop app?

Verified across DSH 0.1.7 ~ 0.2.2 (including 0.2.1-rc.5 and desktop 0.2.2-rc.1 with full ACP and experimental Agent Teams); 0.1.5 handles basic dispatch; 0.2.3+ is unverified (0.2.2+ needs Node ≥ 24.9, fulfilled automatically when running the desktop app's bundled runtime). DSH is auto-discovered in order: desktop app → npm global → npx cache. Call dsh_doctor to check dsh_bin, dsh_runtime, dsh_desktop, and version grade. See the compatibility matrix.

How do I safely uninstall or revert my client configs?

Run dsh-any-agent-setup --remove --yes anytime. It compares against pre-install .bak-dsh-* backups to remove only the dsh-any-agent entry, preserving your original empty containers while deleting files created solely by setup. To revert to any prior snapshot, run dsh-any-agent-restore --list or --latest.

Does the browser demo actually run tasks?

It is a browser-local interactive explanation of the workflow. It does not connect to your machine or call a model. After installing and configuring the MCP server you can dispatch real work from your own client.
