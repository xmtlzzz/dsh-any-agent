On first start it creates a dsh-team profile (team mode is on by default; set DSH_MCP_TEAM=0 to turn it off) and copies the model route from your local DSH config (using the built-in, zero-dependency YAML subset parser). Credentials stay with DSH.

GOOD QUESTIONS

What you may want to know first.

How is this different from calling the DSH CLI directly?＋

This project drives long-lived DSH sessions over ACP: resume history, interrupt turns, handle approvals, and dispatch now while collecting later. The client sees sessions and tasks, not a list of shell commands to execute one by one.

What happens if the editor closes or a process crashes?＋

Persisted sessions can be resumed on the next call. In-flight turns stop when the server or child process exits, and a sentinel may not land. After resuming, check the workspace before dispatching again. A session that dies before its first successful turn may not have reached disk.

Do I need a specific editor, model, or API provider?＋

Any client that can launch a stdio MCP server can connect. Model routing reuses your existing DSH configuration; this project bundles no model credentials and resells no model service. Model usage is billed by your provider.

How do I control write access and approvals?＋

Choose read-only, workspace-write, or danger-full-access. With no env override the server defaults to danger-full-access; setup writes workspace-write into the client config. Out-of-workspace approvals default to auto-allow; pass on_approval=ask when creating a session to adjudicate them. Side effects of external MCP tools are outside DSH's sandbox; read the usage notes first.

Can I operate the same session in the DSH GUI at the same time?＋

One writer per session at a time. While this server holds the lock you can watch progress with dsh_read; to take over in the GUI, call dsh_release after the turn goes idle. Do not let two clients write the same session.

What is team mode, and how do I turn it off?＋

Since 0.4.0 Agent Teams is on by default: DSH can create named teammates when a task needs parallel or multi-role work; simple tasks stay single-agent. Turn it off globally by adding DSH_MCP_TEAM=0 to the client config and reconnecting, or for one call with dsh_send(team=false). Full steps are in the team mode guide.

Does the browser demo actually run tasks?＋

It is a browser-local interactive explanation of the workflow. It does not connect to your machine or call a model. After installing and configuring the MCP server you can dispatch real work from your own client.
