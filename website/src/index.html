GOOD QUESTIONS

开始前，你可能想知道。

首页汇集最关键的机制与限制。深入指南与架构说明可在文档中查阅。

它和直接调用 DSH 命令行有什么不同？#

本项目通过 ACP 驱动长驻的 DSH 会话，支持恢复历史、中断回合、处理审批，以及先派活后收结果。对客户端暴露的是会话与任务，而不是一组逐条执行的 shell 命令。

编辑器关闭，或者进程崩溃，任务会怎样？#

已落盘的会话可在下次调用时恢复。dsh-any-agent-setup --yes 默认开启常驻进程模式（DSH_MCP_DAEMON=1），客户端关闭或重连时回合仍可跑完并写入结果文件。加 --no-daemon 可切回直连 stdio，用 dsh-any-agent daemon status|stop 可管理常驻进程。daemon stop 会经带令牌的本机控制通道优雅触发 hub.shutdown()，刷新注册表、为在跑回合落 interrupted 哨兵、释放子进程锁并清理信息文件。若常驻进程无响应，POSIX 核实启动时间后发送 SIGTERM，Windows 通过同一进程句柄核实启动时间并终止进程。直连模式下，服务正常退出时会保存已经收到的 ACP 结果并将未完成回合记为 stop_reason: "interrupted"；强杀后下次启动也会尽量保留已落盘正文或补写中断哨兵。重连后可用会话 ID 配合原 run_id 或 client_run_id 调用 dsh_get 取结果（只传会话 ID 也能查到最近已开始的回合，支持跨客户端接力）；7 天保留期内即使结果文件已删除，用原幂等键重试 dsh_send 或 dsh_interject 仍会返回原回合 ID（result_available: false）而不会重复派发；升级后既有会话、幂等键与完成文件均可继续使用。回合中断或出现 git_snapshot_incomplete: true 时，先检查工作区再派活。看门狗会取消卡住的回合，默认总时长上限为 2 小时。首次成功回合前中断的会话可能尚未落盘。

需要指定的编辑器、模型或 API 服务吗？#

任何能够启动 stdio MCP 服务的客户端都可以接入。模型路由复用你已有的 DSH 配置，本项目不附带模型凭据，也不代售模型服务。模型调用费用按你使用的服务计算。

如何控制写入权限、沙箱边界与审批？#

可选 read-only（强制 auto-deny 且基于真实沙箱校验 fail-closed）、workspace-write（服务端与 setup 默认值）和 danger-full-access（客户端配置的默认档就是它时直接可用；默认档是别的档、又要按会话单独开完全权限时，才需机器侧设 DSH_MCP_ALLOW_FULL_ACCESS=1）。工作区快照与 worktree 只从宿主 PATH 的绝对路径解析 Git，禁用仓库 .git/config 中的 filter/fsmonitor，并拦截跨盘符软链接与家/根目录越界。调用方和 DSH 要同时改同一个仓库时，可用 dsh_start(isolation="worktree") 让会话在独立的 git worktree 和分支里干活。默认拒绝越界审批。设 DSH_MCP_APPROVAL=ask 后重连，可通过 dsh_inbox 和 dsh_approval_decide 逐条裁决。后台回合使用回执中的等待命令。收到 CHECK_INBOX 时检查审批并继续等待，收到 DONE 时读取结果。外部 MCP 工具按各自服务端的权限执行，不受 DSH 沙箱约束；只读场景请从 DSH profile 移除可写外部服务或改配只读凭据，并在事后核对 tools_used，详见使用注意事项与安全策略。

可以同时在 DSH 的 GUI 里操作同一个会话吗？#

同一会话同时只有一个写者。服务持锁时，在 GUI 中打开是只读的（内容可照常查看，但抢不走写锁）；若会话空闲未持锁，在 GUI 中点开会导致 GUI 永久获取写句柄直至重启 DSH 桌面版 / dsh web。看进度请用 dsh-any-agent watch / dashboard（只读事件文件，不碰写锁），或让 agent 用 dsh_read 增量读取；需在 GUI 交互接手时，先调用 dsh_release。若写锁被失联或其他 MCP 实例占用，dsh_takeover 会在核实持锁进程的系统启动时间后接管（绝不终止 GUI）。完整机制见写锁文档。

怎么看它正在做什么、花了多少 token，支持英文环境吗？#

0.6.1 起可在终端运行 dsh-any-agent watch，或 dsh-any-agent dashboard 打开本地只读网页，展开「客户端 → 会话 → 回合 → 工具调用 / 审批」及实时 token/缓存消耗（仅监听 127.0.0.1 + 一次性 token、脱敏预览、过滤 OSC 52 控制序列，实时事件流始终省略思考正文）。服务端落盘结果默认剥离思考正文。设置 DSH_MCP_SENTINEL_INCLUDE_REASONING=1 时，保留的思考正文仍会经过凭证脱敏。DSH 自身保留 ~/.dsh/sessions 会话日志用于恢复。此外，工具标题/描述、返回值与审核单均已随系统或 DSH_MCP_LANG=zh|en 自动切换中英文，阻塞调用传 progressToken 时每 5 秒推送实时进度。详见用法文档。

团队模式是什么？怎么开启？#

0.5.0 起默认关闭。运行 dsh-any-agent team on 并重连，为新会话开启团队模式。运行 dsh-any-agent team off 并重连，关闭新会话的团队默认设置。DSH 0.2.2-rc.2 起新会话启用共享任务板与普通子代理工具，已有会话保留已保存的团队设置；DSH 0.1.7-rc.1 ~ 0.2.2-rc.1 会将普通子代理工具替换为 9 个实验版团队工具，两种模式的成员均共享同一工作区。dsh_send(team=false) 只关闭实验版团队模式的本次派发提示。完整步骤见团队模式文档。

支持哪些 DSH 版本？如何自动发现桌面版与升级？#

常规 ACP 已验证的 DSH 版本范围为 0.1.7 ~ 0.2.2。Windows 上已从 npm 0.8.0 原地升级到 0.8.1，并在桌面版 DSH 0.2.2-rc.3 下完成 42 个离线套件（2069 项）与 15 个真实模型套件全量实测，验证了重连取回旧结果、继续原会话，以及删除旧结果文件后用原键重试 send 和 interject。此前也在桌面版 DSH 0.2.2-rc.5 上验证了 MCP 0.7.6 → 0.7.7 的升级。从 0.2.2-rc.2 起，团队模式需要 MCP 0.7.4 或更新版本。0.1.5 可做基础派发，0.2.3+ 尚未验证。服务端可从桌面版、npm 全局安装或 npx 缓存探测 DSH。桌面版自带运行 DSH 0.2.2-rc.1 及以上版本所需的 Node.js ≥ 24.9。用 dsh_doctor 查看实际生效的安装（含 DSH_BIN 覆盖）、运行时、团队模式、存储格式及常驻进程数。完整记录见兼容性矩阵。

如果不打算继续使用或想回退配置，如何安全撤销？#

随时运行 dsh-any-agent-setup --remove --yes 即可（加 --only <客户端ID> 可只从单个客户端移除）。工具会对比写入前留存的 .bak-dsh-* 备份，精准摘除 dsh-any-agent 条目：保留用户原本的空容器、JSONC 注释与相邻的 Codex TOML 表，并清理纯新建空文件，绝不破坏其它配置。升级或迁移目录后可用 dsh-any-agent-setup --repair --yes 仅更新启动路径；若需退回历史某次状态，运行 dsh-any-agent-restore --list 或 --latest 按批次安全还原。

网页上的演示会实际运行任务吗？#

这里是用于说明工作流的浏览器本地交互演示，不连接你的计算机，不调用模型。安装并配置 MCP 服务后，才可以在自己的客户端中真实派活。
