GOOD QUESTIONS

开始前，你可能想知道。

首页汇集最关键的机制与限制。深入指南与架构说明可在文档中查阅。

它和直接调用 DSH 命令行有什么不同？

本项目通过 ACP 驱动长驻的 DSH 会话，支持恢复历史、中断回合、处理审批，以及先派活后收结果。对客户端暴露的是会话与任务，而不是一组逐条执行的 shell 命令。

编辑器关闭，或者进程崩溃，任务会怎样？

已经落盘的会话可在下次调用时恢复；进行中的回合会随服务或子进程退出而中断，未完成的哨兵也可能不会写入。恢复后应先核对工作区，再重新派活。正常完成的回合由原子哨兵文件唤醒（Windows 自动附带 PowerShell 原生等待命令），无需轮询。首次成功回合之前的会话可能尚未落盘。

需要指定的编辑器、模型或 API 服务吗？

任何能够启动 stdio MCP 服务的客户端都可以接入。模型路由复用你已有的 DSH 配置，本项目不附带模型凭据，也不代售模型服务。模型调用费用按你使用的服务计算。

如何控制写入权限、沙箱边界与审批？

可选 read-only（强制 auto-deny 且基于真实沙箱校验 fail-closed）、workspace-write（服务端与 setup 默认值）和 danger-full-access（建会话与恢复均须机器侧设 DSH_MCP_ALLOW_FULL_ACCESS=1）。工作区快照会禁用仓库 .git/config 中的 filter/fsmonitor 并拦截跨盘符软链接与家/根目录越界。越界审批默认 auto-allow，每次放行均记入审核单；传 on_approval=ask 可挂起并用 dsh_inbox / dsh_approval_decide 逐条裁决。外部 MCP 副作用不受 DSH 沙箱约束，请阅读使用注意事项与安全策略。

可以同时在 DSH 的 GUI 里操作同一个会话吗？

同一会话同时只有一个写者。服务持锁时，在 GUI 中打开是只读的（内容可照常查看，但抢不走写锁）；若会话空闲未持锁，在 GUI 中点开会导致 GUI 永久获取写句柄直至重启 dsh web。看进度请用 dsh-any-agent watch / dashboard（只读事件文件，不碰写锁），或让 agent 用 dsh_read 增量读取；需在 GUI 交互接手时，先调用 dsh_release。完整机制见写锁文档。

怎么看它正在做什么、花了多少 token，支持英文环境吗？

0.6.1 起可在终端运行 dsh-any-agent watch，或 dsh-any-agent dashboard 打开本地只读网页，展开「客户端 → 会话 → 回合 → 工具调用 / 审批」及实时 token/缓存消耗（仅监听 127.0.0.1 + 一次性 token、脱敏预览、过滤 OSC 52 控制序列，思考内容永不写盘）。此外，工具标题/描述、返回值与审核单均已随系统或 DSH_MCP_LANG=zh|en 自动切换中英文，阻塞调用传 progressToken 时每 5 秒推送实时进度。详见用法文档。

团队模式是什么？怎么开启？

0.5.0 起默认关闭、按需开启：运行 dsh-any-agent team on 并重连，DSH 就能在需要并行或多角色时创建具名成员协作，简单任务不会组队。关闭用 dsh-any-agent team off，单次关闭用 dsh_send(team=false)。完整步骤见团队模式文档。

支持哪些 DSH 版本？如何自动发现桌面版与升级？

官方验证区间为 DSH 0.1.7 ~ 0.2.2（含 0.2.1-rc.5 与桌面版 0.2.2-rc.1，支持完整 ACP 与实验性 Agent Teams 包）；0.1.5 仅基础派发；0.2.3+ 尚未验证（其中 0.2.2+ DSH 需 Node ≥ 24.9，使用桌面版时自动走其自带运行时）。服务端按 桌面版 → npm 全局 → npx 缓存 自动探测 DSH；调用 dsh_doctor 可查 dsh_bin、dsh_runtime、dsh_desktop 与评级。完整对照见兼容性矩阵。

如果不打算继续使用或想回退配置，如何安全撤销？

随时运行 dsh-any-agent-setup --remove --yes 即可。工具会对比写入前留存的 .bak-dsh-* 备份，精准摘除 dsh-any-agent 条目：保留用户原本的空容器并清理纯新建空文件，绝不破坏其它配置。若需将文件退回历史某次状态，也可运行 dsh-any-agent-restore --list 或 --latest 按批次安全还原。

网页上的演示会实际运行任务吗？

这里是用于说明工作流的浏览器本地交互演示，不连接你的计算机，不调用模型。安装并配置 MCP 服务后，才可以在自己的客户端中真实派活。
