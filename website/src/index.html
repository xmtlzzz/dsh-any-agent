GOOD QUESTIONS

开始前，你可能想知道。

首页汇集最关键的机制与限制。深入指南与架构说明可在文档中查阅。

它和直接调用 DSH 命令行有什么不同？

本项目通过 ACP 驱动长驻的 DSH 会话，支持恢复历史、中断回合、处理审批，以及先派活后收结果。对客户端暴露的是会话与任务，而不是一组逐条执行的 shell 命令。

编辑器关闭，或者进程崩溃，任务会怎样？

已经落盘的会话可在下次调用时恢复；进行中的回合会随服务或子进程退出而中断，未完成的哨兵也可能不会写入。恢复后应先核对工作区，再重新派活。正常完成的回合由原子哨兵文件唤醒（Windows 自动附带 PowerShell 原生等待命令），无需轮询。首次成功回合之前的会话可能尚未落盘。

需要指定的编辑器、模型或 API 服务吗？

任何能够启动 stdio MCP 服务的客户端都可以接入。模型路由复用你已有的 DSH 配置，本项目不附带模型凭据，也不代售模型服务。模型调用费用按你使用的服务计算。

如何控制写入权限和审批？

可选 read-only、workspace-write 和 danger-full-access。服务端未设置环境变量时默认 danger-full-access；setup 会把 workspace-write 写入客户端配置。越界审批默认 auto-allow，每次放行与提权均完整记录并汇总进审核单；需要逐条人工裁决时，在建会话时显式设置 on_approval=ask。外部 MCP 工具的副作用不受 DSH 沙箱约束，使用前请阅读使用注意事项。

可以同时在 DSH 的 GUI 里操作同一个会话吗？

同一会话同时只有一个写者。服务持锁时，在 GUI 中打开是只读的（内容可照常查看，但抢不走写锁）；若会话空闲未持锁，在 GUI 中点开会导致 GUI 永久获取写句柄直至重启 dsh web。看进度请用 dsh-any-agent watch / dashboard（只读事件文件，不碰写锁），或让 agent 用 dsh_read 增量读取；需在 GUI 交互接手时，先调用 dsh_release。完整机制见写锁文档。

怎么看它正在做什么、花了多少 token？

0.6.1 起，在终端运行 dsh-any-agent watch，或运行 dsh-any-agent dashboard 打开本地只读网页，按「客户端 → 会话 → 回合 → 工具调用 / 审批」展开调用链；0.6.2 起还显示每回合的输入、输出、缓存命中和上下文占用，回合进行中就会更新。两者都是独立进程，不连 DSH、不碰写锁；页面只监听 127.0.0.1 并要求一次性 token，命令与路径预览先脱敏，思考内容从不写入。详见用法文档。

团队模式是什么？怎么开启？

0.5.0 起默认关闭、按需开启：运行 dsh-any-agent team on 并重连，DSH 就能在需要并行或多角色时创建具名成员协作，简单任务不会组队。关闭用 dsh-any-agent team off，单次关闭用 dsh_send(team=false)。完整步骤见团队模式文档。

支持哪些 DSH 版本？升级时要注意什么？

官方验证并推荐 DSH 0.1.7 及以上版本（支持完整 ACP 接口与实验性 Agent Teams 包）；0.1.5 支持基础派发但无法开启团队模式；0.2.x 尚未验证。可在已连接客户端内运行 dsh_doctor 自检 DSH 版本评级与环境健康；若 DSH 解析自 npx 缓存，doctor 会提示固定路径以防缓存清理失效。完整对照见兼容性矩阵。

如果不打算继续使用，如何安全撤销客户端配置？

随时运行 dsh-any-agent-setup --remove --yes 即可。工具会自动利用写入前留存的逐字节备份，仅精准剔除名为 dsh-any-agent 的条目，将所有客户端配置原样还原，绝不破坏你已有的其它 MCP 服务器与个人设置。

网页上的演示会实际运行任务吗？

这里是用于说明工作流的浏览器本地交互演示，不连接你的计算机，不调用模型。安装并配置 MCP 服务后，才可以在自己的客户端中真实派活。
